# ADR 0016: Algorithm-First Execution Scope

状态：已确认

日期：2026-09-02

## 决策

AURORA-Planner 后续以飞行规划算法和可验证功能为主线。优先完成并验证：

- EGO 语义的三维地图、A*、B-spline、轨迹时间参数化和局部重规划；
- 动态目标跟踪、预测、不确定性传播和时空风险门控；
- 软风险优化、失败回退、轨迹接续和急停状态闭环；
- 能证明上述行为的纯 C++ 测试、最小 ROS 2 适配和确定性三维回放/软件在环。

依赖锁定、发布审计、可视化、PX4/GZ 和真实传感器适配保留为工程支撑与后续集成工作。它们不能替代核心算法验收，也不应在没有对应环境时虚构完成；只有支撑算法正确性所必需的最小接口和测试才进入当前实现切片。

## 理由

项目目标是从 EGO 抽离并重写可独立验证的三维飞行规划核心，而不是先搭建完整机器人软件栈。缩小当前工程化切片可以把实现资源集中到轨迹生成、时间语义、动态预测和风险决策，同时保留未来接入 ROS 2、飞控和仿真的清晰边界。

## 约束

- 不降低为二维车辆导航，也不替换 EGO 的 B-spline、三维搜索、局部重规划和安全门控语义。
- ROS 2 消息、TF、QoS 和执行器适配只在影响核心验证或接口正确性时实现。
- 外部接入未具备运行环境时，记录为未验收，不把软件在环结果表述为真实飞行结果。
- 任何新的核心风险公式、公开消息时间语义或硬安全动作仍需单独记录决策。

## 影响

总体路线图不删除工程化阶段，但调整当前工作顺序：先关闭严格 minimum-snap/时间参数化等核心算法缺口，再补充最小必要验证；PX4/GZ、Humble 实跑和发布合规作为后续独立阶段处理。
