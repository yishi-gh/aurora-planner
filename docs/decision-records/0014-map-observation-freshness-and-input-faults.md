# ADR 0014：地图观测新鲜度与输入故障边界

## 状态

Accepted，2026-09-02

## 背景

AURORA 的静态地图来自异步 PointCloud2 输入，地图内容本身可能仍然存在，但最后一次有效观测可能已经过期。缺失 TF、坏点云、超出点数上限或乱序消息也不能刷新地图时间戳，否则规划器会把没有被新传感器确认的地图误当成新鲜信息。此前动态预测已经有 stale watchdog，需要将地图观测纳入同一类可解释的安全边界。

## 决策

1. 新增 `map.require_fresh_observation` 和 `map.max_observation_age`。生产配置默认启用，默认最大观测年龄为 `1.0 s`。
2. 只有完成点云格式、有限性、点数和 TF 校验，并至少成功处理一个有效点的点云回调，才能更新 `last_map_observation_stamp`。空点云、坏点云、缺失 TF、乱序点云和转换失败均不能刷新该时间戳。
3. 地图 watchdog 与动态信息 watchdog 独立检查；任一信息源过期时停止新轨迹发布。先在 `risk.stale_hold_duration` 内保留仍覆盖当前时刻且重新评估安全的已验证轨迹，保持窗口结束或活动轨迹不再覆盖当前时刻后锁存 `INFORMATION_STALE` 急停。
4. 地图失效进入与动态信息失效相同的恢复边界：清除 pending 请求和自动重规划事件；必须执行显式 reset，随后收到新鲜有效点云和新鲜动态批次，再提交新的显式规划请求。reset 不自动恢复旧轨迹或旧请求。
5. 规划请求的 `header.stamp` 必须相对于已处理规划时钟单调不递减；时间回退返回 `INVALID_REQUEST`，不能用回退时间构造轨迹或更新地图/风险年龄。
6. 仅用于软件在环执行协议的测试夹具可以关闭地图新鲜度约束，但必须通过参数显式声明；专门故障测试保留 watchdog 开启，不能通过修改生产默认值掩盖输入故障。

## 不采用的方案

- 不以“收到过任意点云”作为永久新鲜标志。
- 不在点云转换失败时使用消息 header 刷新地图时间。
- 不由 watchdog 自动清空地图并伪造占据结果；地图状态和信息过期状态分别报告。
- 不因为地图信息过期而自动恢复旧请求或旧轨迹。

## 后果

地图掉线和 TF 故障会更早进入可解释的安全降级，代价是启动和传感器重连后需要重新预热有效点云。基线回放若只提供一次点云，必须显式关闭 watchdog 或提供持续观测；这两种模式不能混为生产默认行为。

## 验证

- `test_planner_faults_ros2.py` 覆盖缺失 TF、坏点云、点云掉线、地图信息 stale、reset 和显式恢复。
- `test_simulation_ros2.py` 显式关闭地图 freshness，验证规划器到三维执行器的接口，不承担地图故障测试。
