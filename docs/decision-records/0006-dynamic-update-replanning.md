# ADR 0006: Dynamic Snapshot Update Replanning

- 日期：2026-09-01
- 状态：已确认并实现第一版
- 范围：`aurora_ros` 动态输入事件与 `StaticReplanFsm`

## 决策

动态障碍物快照不仅用于发布前风险门控，也是一类独立的规划事件。节点收到快照后，如果其有效时间戳严格晚于最近一次规划请求的 `planning_stamp`（允许适配器时间容差），就创建一次主动重规划请求。主动请求复制最近一次完整的三维飞行器状态、全局参考和约束，只把 `planning_stamp` 推进到动态快照时间，并沿用原 `request_id`。

事件以布尔待处理标志跨越 ROS 回调线程和规划线程：规划线程取走 pending 请求时同时取走并清除该标志。相同动态快照时间戳不会再次设置事件；显式 `PlanningRequest` 可以覆盖 pending 请求内容，但不会绕过已经发生的动态事件。

FSM 的触发优先级为：当前轨迹碰撞、安全信息过期、规划失败、动态障碍物更新、地图更新、轨迹接近结束、局部目标过期。动态更新即使没有造成当前轨迹碰撞，也必须进入 `REPLAN`，重新生成并认证候选轨迹。碰撞和信息失效仍优先于普通动态更新。

`REQUEST_REPLAN` 和随后的 `START_PLANNING` 决策保留同一个 `ReplanTrigger`，ROS 2 `PlannerStatus` 使用追加的常量 `DYNAMIC_OBSTACLE_UPDATED=7`，不改变既有枚举数值。

## 原因

只在当前轨迹已经碰撞时重规划会把动态预测退化为事后报警，无法利用新观测提前改道。把“快照变化”和“风险拒绝”分开，可以在当前轨迹仍安全时重新评估未来时空窗口，同时保留硬门控作为最终执行约束。

## 后果

- 空目标但时间更新的有效心跳也会触发一次重新评估，这是动态信息新鲜度变化的显式语义。
- 主动重规划沿用原 `request_id`，调用方必须使用状态/时间和轨迹 ID 区分同一任务的多次结果。
- 该实现按时间戳去重，不对同一时间戳内容变化做二次触发；若未来需要支持这种情况，应为快照增加显式版本号并另行修改契约。
- 主动重规划仍使用最近一次观测到的三维飞行器状态；状态年龄由 `VehicleState.header.stamp` 表达，后续需要接入独立里程计时必须重新确认接续策略。

## 验证

`aurora_planner_core` 的 FSM 单测覆盖动态更新在规划失败之前、地图更新之前的优先级，以及 `REQUEST_REPLAN`/`START_PLANNING` 两步保留同一原因。`aurora_ros` 的真实 DDS 集成测试先建立安全轨迹，再发布较新的非碰撞空动态心跳，验证同一 `request_id=101` 收到成功重规划结果并观察到 `DYNAMIC_OBSTACLE_UPDATED`；随后发布匀速交叉目标，验证动态碰撞仍返回 `VALIDATION_FAILED`、不发布可执行轨迹并锁存急停。
