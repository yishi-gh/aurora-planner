# ADR 0008: Dynamic Replan State Synchronization

- 日期：2026-09-01
- 状态：已确认并实现第一版
- 范围：`aurora_ros` 动态快照主动重规划与轨迹接续
- 关联：修正 ADR 0006 中“只推进 `planning_stamp`”的状态复用细节

## 决策

动态快照触发主动重规划时，不能直接使用最近一次请求中的过期无人机状态。若当前活动轨迹已经通过安全门控、覆盖动态快照时间且在该时间之后仍有有效执行窗口，则从活动轨迹评估位置、速度和加速度，把这些三维状态以及 `vehicle_state.stamp` 同步到动态快照时间，同时推进 `planning_stamp`。

同步后的主动请求继续复用原 `request_id`、全局参考和约束。这样动态目标更新时间、无人机状态时间和轨迹接续边界使用同一时间基准，静态安全门控可以正确检查新旧轨迹连续性。

若活动轨迹不存在、未验证、不覆盖动态快照时间、已到达末端或评估结果非有限，则不创建基于过期无人机状态的主动重规划请求。动态快照仍保存用于后续请求，节点输出警告并等待新的显式 `PlanningRequest` 提供当前无人机状态。

## 原因

动态目标可能在上一条规划结果发布后较晚更新。只推进规划时间而保留旧位置会使新候选轨迹与活动轨迹在起点处不连续，既会误报 `CURRENT_STATE_DISCONTINUITY`，也可能让规划器从过期状态生成不适合执行的轨迹。使用已验证轨迹的名义状态可以在缺少同步里程计消息的首版 ROS 2 适配中保持时间连续；后续接入独立里程计时，显式状态仍应优先于轨迹名义状态。

## 后果

- 同一动态任务仍沿用原 `request_id`，但每次主动重规划的 `planning_stamp` 和同步后的车辆状态时间会推进到动态快照时间。
- 当前实现只在活动轨迹覆盖该时间时自动重规划；轨迹过期或时间超出覆盖范围时采用失败关闭，等待显式状态输入。
- 轨迹名义状态不包含真实跟踪误差；跟踪协方差、执行延迟和飞控反馈仍需在统一风险策略阶段接入，不能把本决策当作状态估计器替代品。

## 验证

`test_stopping_rosbag2_replay.py` 以同一 `request_id=2901` 回放刹车状态和停止状态：两个动态时间点均成功规划，动态重规划状态至少出现两次，所有轨迹均为 `VALIDATED`，且没有急停锁存。修复前停止时间点返回 `VALIDATION_FAILED/CURRENT_STATE_DISCONTINUITY`；修复后该结果消失。`test_dynamic_rosbag2_replay.py` 和 `test_acceleration_rosbag2_replay.py` 仍验证动态交叉目标的高风险拒绝和急停锁存。
